[chant](https://intentius.io/chant/) is typed infrastructure end to end: TypeScript in, spec-native output out, with the lifecycle (observe, reconcile, apply) built on top of a synthesis core that runs no project code. The specification here was extracted from its fold mechanism and now owns it; chant implements the specification and declares which version.

## Author

A resource is a typed object: `new Bucket({ BucketName: ... })`, with the target spec's own property names and casing, so what is authored is what ships. Seventeen lexicons supply the types, from generated schemas: AWS CloudFormation, Azure ARM, GCP Config Connector, Kubernetes, Helm, GitHub Actions, GitLab CI, Fly, Terraform, and more.

## Check

Evaluability lint (is this file data) at the keystroke, then each lexicon's semantic rules over folded values, then post-synth checks over the emitted artifact. The rules are the lexicon's; the contract they run under is what [issue #79](https://github.com/INTENTIUS/typescript-as-data/issues/79) writes down.

## Generate

Three generators through one pipeline: `chant import` from an existing template, `--from <env>` live import through each lexicon's `exportResources()`, and carve-out from Terraform. Generated source folds back to the artifact it came from; the Kubernetes lexicon carries a round-trip suite, and [issue #80](https://github.com/INTENTIUS/typescript-as-data/issues/80) states the property.

## Proof

chant {figures.chantPin} passes every fixture it can answer, and agrees with the reference implementation on every one. Over chant's own example corpus, {figures.corpus.entries} projects and {figures.corpus.files} files at `{figures.corpus.revision}`, the two implementations agree on all {figures.corpus.comparable} comparable files and produce identical export namespaces on the {figures.corpus.bothFold} that fold on both sides. The limits that make the other files incomparable are counted, not hidden: [the corpus cross-check](/typescript-as-data/conformance/corpus/).
